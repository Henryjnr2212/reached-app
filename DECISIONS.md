# Decisions

Judgment calls made where the spec was open or ambiguous, newest last. Each one says what was chosen and why, so it can be changed on purpose later.

## Product

1. **Default arrival behaviour: send automatically.** Spec §14 lists this as the current default. "Ask me first" is a setting; if ignored it sends after 5 minutes (also 10 min or Never).
2. **Minimum age: 16.** Teenagers aged 13 to 15 can use Reached only when a parent or guardian sets it up on their phone and is one of their emergency contacts. Under 13 cannot use it. Stated in the Privacy Policy and Terms. Ghana's Data Protection Act treats under-18s as children, so the parent route keeps a responsible adult in the loop.
3. **Free plan limits:** 5 contacts, 10 places, 30 arrival-type texts a month (arrived, on the way, running late, plans changed). Overdue alerts, SOS, all clear and intro texts are never counted and never blocked. Premium (GHS 15/month) is 15 contacts, 15 places and 300 texts; Family (GHS 40/month) adds up to 5 members. Places are capped at 15 for everyone because iOS monitors at most 20 regions per app and we keep headroom. Limits live in `packages/core/src/plans.ts` and are enforced by the database (`private.enforce_limits`).
4. **When the SMS allowance is used up (spec §13):** arrival messages to contacts who accept WhatsApp go by WhatsApp; SMS-only contacts get no arrival text that month and the user sees "Monthly text allowance used" on the event with an upgrade link. Safety messages always go out.
5. **Replies and opt-outs:** use a two-way Africa's Talking short code or long number for STOP and REACHED (a branded "REACHED" sender ID cannot receive replies). WhatsApp replies are handled too. Until the two-way number is live, the intro text still says "Reply STOP to opt out" and the inbound webhook is ready.
6. **Duplicate window:** the same place can't send the same message to the same contact again within 1 hour (spec §13, bouncing at the zone edge). Two rules firing together become one message per contact.
7. **"I'm not sure yet" (Phase 1 hid it; Phase 2 enables it):** without a destination, the trip uses auto-detect for arrival and the late check uses the 30 min / 1 hr / 2 hrs / Custom options.
8. **"Edit trip"** is implemented as cancel quietly + start a new trip pre-filled with the old one. Contacts see nothing unless the new trip tells them something. This keeps trip state on the server simple (no partial edits of a live trip).
9. **"I'm safe now" confirmation:** phone unlock (fingerprint, face or PIN) through expo-local-authentication. If the phone has no screen lock at all (or on the web build), it falls back to a confirm sheet. A separate in-app PIN was left out of Phase 1: almost every phone in the target market has a lock, and a forgotten app PIN during an emergency is worse than the risk it removes. Revisit with the Phase 3 duress PIN.
10. **Payment provider (Phase 3):** behind a `PAYMENTS_MODE=fake|live` switch with one generic mobile money/card API shape (MTN MoMo, Telecel Cash, AT Money, card). The actual provider (e.g. Hubtel or Paystack) is a business decision; see MANUAL_TESTS.md.
11. **Police (Phase 3):** the station list and the "Also alert the police" switch ship, but police data is marked unverified and the switch stays hidden until a partnership is signed (`police_stations.verified`). Emergency numbers shown are 112 (all), 191 (police), 193 (ambulance), 192 (fire); confirm with the Ghana Police Service before launch.
12. **Translations (Phase 2):** Twi, Ga and Ewe message templates are drafts written to fit 160 GSM-7 characters. They must be checked by native speakers before launch (MANUAL_TESTS.md).
13. **Live location links** expire when the trip ends, or 2 hours after an alert is cleared. Tokens are 8 random characters from an unambiguous alphabet.

## Messages

14. **"–" (en dash) in the spec templates is sent as "-".** The en dash is not in the GSM-7 alphabet; one en dash turns the whole SMS into UCS-2 and cuts the limit from 160 to 70 characters. A unit test checks every template with long realistic names and places stays GSM-7 and within 160.
15. **Overdue alert with check-ins stopped** adds "Ama's phone may be off." and shortens the place name if needed to stay within 160.

## Engineering

16. **Styling: React Native StyleSheet + a single token file instead of NativeWind.** The design is driven by tokens shared with the web app (`packages/core/src/tokens.ts`), with light/dark built from the same names. NativeWind would have added a second styling system and build step for no visual gain, and its SDK 57 support lagged. CLAUDE.md allows this when the design calls for it.
17. **Design direction:** map-first Home with floating round controls, a red SOS shield, soft white cards, pill chips, a dark pill primary button and a floating dark tab bar, based on the uploaded samples and `design-reference/`. Font: Plus Jakarta Sans. Calm green primary (#0A7550) with a near-black accent.
18. **End-to-end tests run in a browser, not on an Android emulator.** This build environment has no Android emulator or KVM. `pnpm test:e2e` runs Playwright against (a) the Next.js site and (b) the Expo web export of the mobile app with an in-memory demo backend that follows the same rules as the database (overdue timing, duplicates, STOP, plan limits), at 360dp in light and dark with mocked GPS. The Maestro flows in `.maestro/` cover the device-only parts (background location, notifications, permissions) and are listed in MANUAL_TESTS.md.
19. **`pnpm test:db` without Docker:** uses `supabase test db` when a local stack is running; otherwise it starts a throwaway Postgres with pgTAP and pg_cron, applies a small shim for Supabase's `auth` schema and roles, then runs the same test files.
20. **Phone sign-in:** Supabase Auth phone OTP with the "Send SMS" auth hook pointing at our `send-sms` function, which sends through Africa's Talking (or FakeProvider). The OTP SMS includes the Android SMS Retriever hash so the code fills itself in. Local development uses Supabase test OTPs (`+233241234567` → `123456`).
21. **Trip state and the overdue check live in Postgres functions** called by the app and by pg_cron every minute. The phone only reports arrival and check-ins; if it dies, the server still escalates.
22. **Precise locations are never logged.** Location pings are deleted after 30 days by `cleanup_data()` (daily cron), and activity follows the user's 7- or 30-day setting.
23. **Foreground tracking fallback:** when the user hasn't granted "Allow all the time" (and on the web build), the same tracker runs while the app is open. A zone the phone is already inside at the first reading is marked as arrived silently, so opening the app at home doesn't text everyone.
24. **Arrival detection** needs a 90-second minimum stop inside the zone and doesn't count while the phone reports being in a vehicle (or moving faster than 4 m/s), per spec §13 "Traffic / waiting at a station".
25. **Offline arrivals (spec §13 "No data at arrival"):** arrivals and departures that can't reach the server are kept on the phone (`apps/mobile/src/lib/outbox.ts`) and retried every 30 seconds and whenever the connection returns. After 5 minutes still offline, the app opens the SMS app with the arrival text ready (in the background it shows a notification that leads there). The queued report still reaches the server later so the trip ends and the overdue check stops; if the user already texted by hand, contacts may get the arrival twice, which we accept over a missed arrival. Reports the server refuses (trip already ended) are dropped.
